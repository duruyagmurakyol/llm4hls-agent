# `benchmarks/`

Committed benchmark inputs used to exercise the agent. A benchmark is data: source, headers, self-checking testbench and a Vitis build description. Agent logic must not live here.

## Retained benchmark families

The submission tree keeps representative inputs for:

- `vector_add/` — baseline and repair faults;
- `bicg/golden/` — original BiCG benchmark;
- `bicg/u55c/` — committed U55C-targeted BiCG regression package;
- `hls_eval/atax/` and `hls_eval/gemm/`;
- `repair_suite/` — dot-product and GEMM repair cases;
- `hard_smoke/` — harder optimisation kernels;
- `capability_suite/` — generate, synthesis-fix and structural tasks;
- `structural_diversity/` — streaming/dataflow-style cases.

Official FPT Track-A packages are external evaluator inputs and are not copied into this directory.

## Supported layout

Typical `task.cfg` benchmark:

```text
benchmark/
├── src/
│   ├── kernel.cpp
│   └── kernel.h
├── testbench/
│   └── kernel_test.cpp
└── task.cfg
```

Example:

```ini
[hls]
flow_target=vivado
syn.file=src/kernel.cpp
syn.cflags=-Isrc
syn.top=kernel
tb.file=testbench/kernel_test.cpp
tb.cflags=-Isrc
part=xcu55c-fsvh2892-2L-e
clock=10ns
```

The onboarding layer also supports compatible TCL-based benchmark descriptions.

## Run a benchmark

```bash
python3 scripts/run_agent.py benchmarks/vector_add --onboard-only
python3 scripts/run_agent.py benchmarks/bicg/u55c --mode optimise
```

The benchmark source is treated as immutable input. Candidate workspaces and Vitis outputs are written under ignored experiment/result directories.

## What is not committed

Do not store generated Vitis projects, `.Xil`, candidate archives, model responses, synthesis logs or run summaries inside `benchmarks/`. Those are regenerated by the agent and intentionally excluded from source control.

Some historical experiments used generated/imported benchmark copies under ignored directories. Retained submission experiments should point to a committed benchmark here or to an explicitly external organiser task package.
